# P015 stream backpressure design

The producer uses a bounded 514-record channel: one session, at most 512 device records, and one terminal. The existing 2 KiB record and 512 KiB total output limits further bound serialized memory. This choice permits the entire allowed burst without awaiting stdout in the BlueZ task. A full channel is still an error, but cannot occur for valid records within these limits. Sequence numbers and counters advance only on successful enqueue. The single writer preserves FIFO order and acknowledges only after write and flush.

While records are outstanding, two seconds without an observed completed write signals `output_blocked`; an acknowledged write resets the deadline. Failure is `output_closed`. The scan timer and cancellation race the async collection future, which polls writer progress and BlueZ ownership; no producer thread blocks on channel send. Cleanup runs before any terminal enqueue, and the terminal must itself be acknowledged before a successful exit. A blocked writer thread is not joined: process exit ends it after bounded cleanup. With progress, the finite record budget also bounds drain time, although a very slow reader can take substantially longer than two seconds in total. Qt's independent process deadline can force termination before such a drain completes, in which case cleanup is reported uncertain. A lost Start reply remains uncertain and does not authorize Stop.
