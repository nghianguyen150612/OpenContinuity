# P018 offline evidence validation and privacy

`scripts/p018_watch_trial_evidence.py FILE` checks the strict operator envelope described below. To correlate actual exports, pass `--host HOST.json --watch WATCH.json`; a single `--host FILE` or `--watch FILE` produces a `valid_partial` report that lists the missing source. This reads only the named local files. It performs no network, D-Bus or Bluetooth action. Each file is capped at 128 KiB; duplicate keys, unknown fields, malformed types, bad sequences, invalid relative times, unknown events, inconsistent registration/cleanup/terminal states and mismatched trial labels fail with a fixed sanitized error. Watch event and stage timing is monotonic relative time; exported samples omit wall-clock timestamps. Differing source claims are summarized as alignment categories without selecting a winner. The report never echoes raw inputs or paths.

The host file is the exact `gatt_trial_diagnostics` schema; the Watch file is P007B `diagnostic_trace` v2. The caller must copy the Watch's displayed local trial label into Linux `--trial-id` to produce matching exports. It is possible to copy a label incorrectly or fabricate either file. The validator marks both files as user-supplied and unverified, labels the Watch `source` only as a source claim, and says endpoint communication is unauthenticated. Truncated or unterminated Watch captures return partial structure, not a complete trial.

Pair output reports only structurally shared P006 observations and P009 Watch request/consent observations. It never emits `pass` for physical qualification. The existing single-envelope mode remains useful for sanitized operator records and has sources `mock_ci`, `host_runtime_observed`, `watch_runtime_observed`, `operator_declared`, and `independent_observer`; a schema-valid declaration is not attestation. All results say `physical_qualification: not_qualified` and `authorization: never_evaluated`.

Do not include MAC addresses, names, D-Bus paths, RSSI, raw advertisements, payloads, signatures, keys, enrollment material, identity strings, exception text or private paths in manually prepared envelopes. Keep runtime exports local and delete them after review. Software fixtures, host observations, Watch observations, operator statements and independent RF measurements remain distinct evidence sources.

## Manual stage observation schema v1

The positional `FILE` mode accepts exactly these top-level fields: `schema_version` (integer `1`), `trial_id` (32 lowercase hex characters), `stage` (`W0`–`W6`), `source` (`mock_ci`, `host_runtime_observed`, `watch_runtime_observed`, `operator_declared`, or `independent_observer`), `result` (`pass`, `fail`, `blocked`, or `not_run`), `authorization` (exactly `never_evaluated`), and `events` (0–64 fixed records). Each event has exactly `sequence` (contiguous zero-based integer), `elapsed_ms` (monotonic relative integer no greater than 3,600,000), `phase` (`start`, `registration`, `discovery`, `transport`, `decision`, `cleanup`, or `terminal`), and `outcome` (`attempted`, `confirmed`, `failed`, `cancelled`, `expired`, `unknown`, or `complete`). No free-text notes or imported payload are accepted.

For a claimed pass/fail, events must begin with `start/attempted`, include cleanup, and end with a terminal state. A pass also needs a confirmed cleanup and complete terminal; its output remains only a claimed result and hardware stays unqualified. `not_run` and `blocked` may have no events to record a gate that could not be attempted. Operator and independent-observer records remain separate files and provenance labels; matching a runtime export's trial ID is not proof that the observer watched that endpoint.
