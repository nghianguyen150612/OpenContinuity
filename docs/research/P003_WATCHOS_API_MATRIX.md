# P003 watchOS public API matrix

**Evidence snapshot:** 2026-10-28. API availability is based on Apple documentation and WWDC material, not an Apple SDK build. Use an Apple Xcode toolchain to confirm deployment-target signatures before writing Swift. Current Linux environment has no `xcodebuild`; no companion app was made.

| API / behavior | watchOS evidence | Permissions, entitlement, and limits | Classification for SE 2 / P003 |
| --- | --- | --- | --- |
| `CBCentralManager`, `CBPeripheral` | Apple documents CoreBluetooth on Apple Watch and direct Watch connection to Bluetooth peripherals. CoreBluetooth central scan/connect/GATT role is the candidate direct topology. | Include the Bluetooth purpose string required for CoreBluetooth use where applicable (`NSBluetoothAlwaysUsageDescription`; verify the Watch target's SDK behavior). Background work needs the documented WatchKit Bluetooth background mode/task configuration. | **DOCUMENTED** API; physical SE 2 test **NOT RUN**. |
| `CBPeripheralManager` service hosting / advertising | Apple explicitly says service advertising using `CBPeripheralManager` is unavailable in watchOS. | No public app entitlement was found that lifts this restriction. Do not assume iOS peripheral APIs are available on Watch. | **BLOCKED** for Watch-hosted GATT service advertising. |
| CoreBluetooth in background | Apple describes connecting/reconnecting and receiving peripheral data through watchOS 8+ background tasks; watchOS 9+ may keep a peripheral connection while the app is suspended. | Add `bluetooth-central` to the Watch app background modes per WatchKit guidance. App must initiate relevant work and obey WatchKit scheduling. Background refresh can be disabled or delayed. No general continuously-running daemon/listener contract. | **DOCUMENTED, constrained**; unattended responder **BLOCKED** by missing guaranteed wake/runtime. |
| WatchKit background refresh tasks | WatchKit launches tasks for defined conditions and grants brief execution; Bluetooth accessory refresh path is documented. | Task must finish and report completion. Scheduling and time are system-controlled. Do not promise a challenge response deadline from task delivery. | **DOCUMENTED**; arbitrary on-demand launch **UNKNOWN/BLOCKED**. |
| `WKExtendedRuntimeSession` | App can continue after user stops interacting and even after display sleeps; Bluetooth communication is among possible activity. | Only one session type per app: self care (frontmost, max 10 min), mindfulness (frontmost, max 1 hr), physical therapy (background, max 1 hr), or smart alarm (background/schedulable, max 30 min). Must choose a session type based on app purpose; cannot choose it just to obtain background runtime. User can leave frontmost app. | **DOCUMENTED**, narrow use cases; not a continuously available unlock service. |
| `URLSession` | WatchOS apps can make network requests routed through paired iPhone, known Wi-Fi, or Watch cellular. Apple recommends URLSession for URL loading. | Test each route. Network Framework and raw socket APIs have watchOS-specific support; no arbitrary raw BSD socket assumption. Local-IP host route and LAN discovery are not established by the cited guide. | **DOCUMENTED** networking; direct LAN to Linux **UNKNOWN** pending build/hardware test. |
| Local network privacy / Bonjour | Apple's TN3179 platform matrix says local network privacy is **not** supported on watchOS. The API still needs to be documented per actual framework/build. | iOS's `NSLocalNetworkUsageDescription` prompt and multicast entitlement requirements cannot simply be copied to watchOS. No watchOS local discovery/permission behavior was hardware-tested. | **DOCUMENTED** platform distinction; actual LAN API operation **UNKNOWN**. |
| `WCSession`, `WatchConnectivity` | Framework provides two-way communication between companion iOS and watchOS apps. `sendMessage` is immediate only for a reachable active counterpart; `transferUserInfo` is queued background transfer. | Both apps need WatchConnectivity target setup and delegate/session activation. Reachability indicates app-to-app communication readiness, not wearer presence. Background queue is not immediate and delivery may be delayed. | **DOCUMENTED**; paired device tests **NOT RUN**. |
| `LAContext`, `LAPolicy.deviceOwnerAuthenticationWithWristDetection` | Apple documents the Watch policy for watchOS 9+. Evaluation fails without Watch passcode set/entered or if Watch detected removal from wrist. | User interaction is local to the Watch; error, cancel, unsupported policy or no passcode denies. This verifies a system policy, not a signature or remote identity. It is not Touch ID or a third-party biometric endpoint. | **DOCUMENTED** API; actual approval UX and binding test **NOT RUN**. |
| CryptoKit P-256 / Secure Enclave | Apple documents CryptoKit public-key operations and P-256 signing through Secure Enclave; `SecureEnclave.isAvailable` is the runtime support check. | Create a non-exportable key where available, store public enrollment binding, and make access contingent on the selected Local Authentication operation. Confirm keychain access-control semantics, deletion/revocation and runtime availability in the actual Watch SDK/device. | **DOCUMENTED** API family; SE 2 app-key accessibility and auth binding **UNKNOWN** until physical test. |
| watchOS biometrics | SE 2 specifications list optical heart sensor, not Touch ID. Reviewed Local Authentication API describes Watch passcode and wrist detection. | Do not use heart rate/sensor readings as identity, biometric match, or approval. Do not claim a third-party Touch ID/Face ID API on Watch. | No third-party biometric approval API established; passcode/wrist route only. |
| Notifications / app launch | Notification interactions and defined background events exist, but Apple does not document arbitrary Linux push as a guaranteed local Watch wake mechanism. | Notification delivery is subject to system and user state. Approval must open an app UI and bind to a live session; a delivered notification alone is no presence. | **UNKNOWN** as challenge wake route; not a primary P003 transport. |
| Entitlements and privacy prompts | Public APIs and standard target capabilities are the only allowed basis. | No private entitlement, Apple Account credential extraction, private pairing record or internal Auto Unlock API is used or requested. For iOS LAN/Bluetooth companion work, follow the appropriate public purpose strings and local-network entitlement rules. | Public-only constraint. Apple target build remains **BLOCKED** on Xcode absence. |

## Supported target choice for any later companion experiment

Use a watchOS 9+ deployment target for the documented wrist-detection policy and suspended BLE connection behavior. This is a proposed lower bound for experimentation, not an implemented project support promise; check that Xcode's selected SDK and current Apple device support it. An iOS companion target should use its own iOS deployment floor based on available WatchConnectivity and permissions. No Xcode project or Swift source is included in P003.
