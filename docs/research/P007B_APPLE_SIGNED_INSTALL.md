# P007B signed Apple Watch SE 2 installation

`authorization: never_evaluated`

Status in this environment: NOT RUN. Hosted unsigned compilation is a separate gate; no physical Mac, signing session, paired iPhone or Watch is attached here.

1. Use a Mac with Xcode and an installed watchOS SDK compatible with the Watch's installed OS. Prior CI qualification used Xcode 16.4/watchOS 11.5; record current `xcodebuild -version`, `xcodebuild -showsdks`, `swift --version` and `xcodegen --version`. Target minimum is watchOS 10. Upgrade Xcode when a physical device's OS requires newer device support. Do not downgrade device OS to satisfy this guide.
2. Pair the owned SE 2 with an iPhone using Apple's normal setup. Connect/trust that iPhone in Xcode Devices and Simulators, enable Developer Mode where the OS requires it, and wait until the paired Watch appears as an available device destination. Record models and OS versions, never UDIDs/serials. Follow Xcode's on-device preparation prompts; do not modify system Bluetooth pairing from the app.
3. Install XcodeGen (qualified version 2.46.0). From the repo root run `xcodegen generate --spec experiments/watchos/project.yml`, then open `experiments/watchos/OpenContinuityWatch.xcodeproj`. Select scheme OpenContinuityWatch and the physical paired Watch destination rather than a generic/simulator target.
4. Select the app target's Signing & Capabilities. Choose an authorized development team, a unique bundle identifier, automatic signing if appropriate, and override the generated `CODE_SIGNING_ALLOWED=NO` to YES for the device configuration. That NO setting is intentional for CI. Allow Xcode to create/select valid development provisioning. A paid team is not required for unsigned CI; device provisioning eligibility/entitlements depend on the account and installed Xcode. Report exact provisioning errors without sharing account/team/profile identifiers. Do not commit signing settings containing identifiers, certificates, profiles or keys.
5. Build and Run on the Watch. A CLI equivalent for an already provisioned setup is `xcodebuild -project experiments/watchos/OpenContinuityWatch.xcodeproj -scheme OpenContinuityWatch -configuration Debug -destination 'id=<private-device-id>' CODE_SIGNING_ALLOWED=YES DEVELOPMENT_TEAM=<private-team-id> CODE_SIGN_STYLE=Automatic build`. This builds; use Xcode Run for install/launch. Do not copy the private destination/team command to published evidence. The standalone Watch app declares WKApplication/WKWatchOnly; an iOS companion app is not included.
6. Open the app in the foreground; accept the Bluetooth prompt. Verify the usage description explains the experimental connection. No scan should begin before Start Scan. If denied, use the device's normal privacy settings manually; never silently change permissions. Pairing to Linux is not an installation prerequisite or an authentication step.
7. If installation fails, inspect destination readiness, trusted iPhone/Watch connection, Developer Mode, OS/SDK compatibility, unique bundle ID, provisioning validity and CODE_SIGNING_ALLOWED override. Separate BUILD, SIGN, INSTALL and LAUNCH failures in evidence. If the Watch cannot be selected, installation is BLOCKED even when the unsigned generic build succeeds.
8. End the trial with Disconnect, disable Diagnostics to discard metadata, and stop the Linux server. Delete the app using the Watch's normal app removal UI (or the paired iPhone's Watch app where available). Clear private local logs/profile exports after retaining sanitized evidence according to the operator's policy. No app state is enrolled with Linux.
