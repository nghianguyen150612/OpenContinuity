# P018 GATT lifecycle security review

## Implemented boundaries

P006 and P009 retain the existing service UUIDs, frame formats, radio guard, explicit runtime bounds, pinned BlueZ owner and owned-resource cleanup. Diagnostics are opt-in through `--diagnostics`, behind the existing `--experimental` guard. They store fixed enums, a random local trial label, monotonic relative time and bounded counters. After the owned advertisement/application cleanup attempt, the Linux host trace makes one bounded-size best-effort write to stderr through `/proc/self/fd/2`, opened with `O_NONBLOCK|O_APPEND` as a separate file description. It does not use `dup` or change the original descriptor's status flags. For a pipe, the <=2 KiB JSON line plus newline is less than Linux `PIPE_BUF`; one nonblocking write is atomic, either delivering the complete line or dropping it when the pipe has insufficient capacity.

Before that write, the calling thread temporarily blocks `SIGPIPE`. If the write fails with `EPIPE`, it consumes only a newly pending `SIGPIPE` generated by this write, then restores the prior thread signal mask. It does not change the process-wide signal disposition. A closed/full pipe, unavailable procfs, or failed reopen produces no record. A failed or short write is not retried or reported as success; non-pipe destinations could retain a partial fragment, which the host evidence loader rejects unless it is one complete newline-terminated JSONL record. Missing or invalid output is unavailable evidence and can never establish a successful trial. GATT callbacks only attempt a short in-memory `try_lock`; contended records mark evidence incomplete. The output is capped at 15 regular events plus terminal and 2 KiB.

The Watch reuses P007B storage, is disabled by default, caps event/sample history, exports at most 16 KiB and clears capture on opt-out/background. It records fixed events without peer identifiers, payloads, signatures, enrollment material or callback descriptions. Stale generation callbacks are rejected. Explicit foreground scan remains required.

The evidence checker rejects duplicate JSON keys, unknown fields, malformed and oversized records, sequence/timing/phase errors, missing terminals and mismatched labels. Its summary is never a physical qualification verdict. Submitted files and shared labels are unauthenticated.

## Limits and residual risk

BlueZ's server-side D-Bus method reply does not expose a remote peer ACK callback; host records the local operation, not peer receipt. Host and Watch clocks are independent and are never compared. The host trace does not export free-form BlueZ error strings or private resource paths. The source reports no device identity, and a local label can be copied or fabricated. The private fake BlueZ integration suite covers existing registration/cleanup behavior, while P018's new Rust trace test exercises the production P006 state path; it does not invoke a real controller.

No RF cleanup, real Wayland, signed Watch install, SE 2 callback behavior, long-read interoperability, wearer identity, proximity, Apple identity, or login authorization is established. P010 remains NO-GO; native Auto Unlock remains NO-GO. `authorization: never_evaluated`.

P018A's liveness guarantee is specifically about pipes/FIFOs: they receive one complete JSONL record or no record, and a full or readerless pipe cannot block or terminate the process through SIGPIPE. The offline host-export loader requires exactly one newline-terminated line, so a partial non-pipe write that stops just after syntactically complete JSON is rejected. Diagnostics are emitted only after owned BlueZ cleanup has been attempted, so a slow non-pipe stderr destination cannot delay that cleanup; this design does not promise that arbitrary filesystem, terminal, device, procfs, or `close()` I/O cannot delay process return. Output remains best-effort and may be absent. Linux subprocess tests cover normal complete output, readerless-pipe SIGPIPE handling, a full-pipe exit bound, unchanged original descriptor flags, unavailable procfs, and failed descriptor reopening.
